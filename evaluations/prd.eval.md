## 4. Red Team Analysis (7 Failure Modes)

1. **Failure Mode 1 (Technical - Numeric Input Exploit in FR-13):**
   - *Why dangerous:* A judge types `-5000`, `0`, or `9999999999` into "Try your own cap" (`FR-13`), causing division-by-zero or negative payable values, crashing the React UI.
   - *Probability:* High | *Severity:* Critical
   - *Mitigation:* Wrap `advice.ts` and UI handlers in strict sanitizers: `cap = Math.max(1000, Math.min(policy.sumInsured, Math.floor(Number(val) || 0)))`.
2. **Failure Mode 2 (Technical - SI Clamp Line Item Mismatch):**
   - *Why dangerous:* When SI clamp triggers (`FR-6`), total `insurerPays` drops, but individual line items still sum to the un-clamped total, causing FR-7 ($billed - insurerPays == \Sigma deductions$) to fail in the line audit drawer.
   - *Probability:* Medium | *Severity:* High
   - *Mitigation:* Emit a dedicated `SI_CLAMP` line item in `LineResult` with a negative payable adjustment equal to the clamped difference.
3. **Failure Mode 3 (Product - The Dual Finisher Trap):**
   - *Why dangerous:* The developer spends Saturday splitting effort between Finisher A (Live read) and Finisher B (Appeal drafter), shipping two half-broken features instead of one polished finisher.
   - *Probability:* High | *Severity:* Critical
   - *Mitigation:* Hardcode a decision rule: execute Finisher B first; only touch Finisher A if Finisher B passes end-to-end testing before 2 PM Saturday.
4. **Failure Mode 4 (Security - Client-Side Memory Leak of Sensitive Data):**
   - *Why dangerous:* If a judge uploads an unofficial test document, parsed strings remain cached in unmanaged React state or localStorage, accessible via developer tools.
   - *Probability:* Low | *Severity:* Medium
   - *Mitigation:* Enforce zero local storage persistence and add automatic state reset on route unmount.
5. **Failure Mode 5 (Execution - Performance Degradation on Budget Phones):**
   - *Why dangerous:* React re-renders the entire 8-scene landing page on every slider tick, dropping frame rate to <30 fps on budget Android devices and failing NFR-4.
   - *Probability:* High | *Severity:* High
   - *Mitigation:* Isolate the slider state in a localized Zustand store or React Context, ensuring only the Receipt component re-renders during drag gestures.
6. **Failure Mode 6 (Project-Specific - Tour Desynchronization):**
   - *Why dangerous:* The 90-second tour (`FR-14`) attempts to scroll to elements that have not yet loaded or finished animating, causing the automated camera to get stuck in blank whitespace.
   - *Probability:* Medium | *Severity:* High
   - *Mitigation:* Implement explicit waypoint element detection with a 500ms safety timeout before triggering camera pans.
7. **Failure Mode 7 (Project-Specific - Metrics Gate Failure on Sunday):**
   - *Why dangerous:* The CI build fails at 5:30 PM on Sunday because `metrics.json` still has an unintentional `"TBD"` placeholder (`prd.md:86-87`), blocking deployment 30 minutes before submission.
   - *Probability:* Medium | *Severity:* Critical
   - *Mitigation:* Create a default seeded `metrics.json` populated with verified baseline test results during Day 1 scaffolding.
